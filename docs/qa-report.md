# QA検証レポート: 防災ハザードマップ & 避難場所表示 静的HTMLアプリケーション
## （第2版: ジオコーディング高精度化・スマートリランキング・候補UI検証）

本書は、システムアーキテクチャ設計書（`docs/architecture.md`）、実装計画書（`docs/implementation-plan.md`）、およびシニアコーダーの実装コード群（TASK-009 〜 TASK-015）に対して、QAエンジニア（コードレビュー・検証担当）が12大検証項目に基づき客観的・網羅的な検証を実施し、潜在障害モードおよび不具合を検出・記録したレポートである。

## 1. 検証サマリー

- **テスト実施ステータス**:
  - **実行済み**:
    - 全49テストケース（既存テスト39件 ＋ QA第2版徹底検証テスト10件）を Node.js 組み込みテストランナー（`node --test tests/*.test.js`）にて自動実行し、全件の稼働および検証エビデンスを取得。
    - 実外部API通信環境において、「新宿駅」「渋谷駅」「博多駅」「新大阪駅」「東京タワー」「zzxyy9999」の検索を行い、意図しない遠隔地小字（山形県朝日町、福島県猪苗代町、北海道松前町、千葉県神崎町等）が上位から完全に排除され、目的地の正しい候補が高スコア（120〜140点超）かつ高確度で提示されることを実機実証。
  - **検査済み**:
    - `index.html`, `css/style.css`, `js/config.js`, `js/geocoding-service.js`, `js/ui-controller.js`, `js/app.js` の全ソースコードに対する静的コード解析、正規表現パターン照合、DOM描画パスのサニタイズ（XSS耐性）検証、および非同期制御パスのレビューを完了。
  - **推論済み**:
    - OSM Nominatim API のレート制限（1 req/sec）到達時における HTTP 429 エラー発生確率と、ブラウザごとのフォーム Enter キー押下時の submit イベント多重発火挙動。
  - **未検証**:
    - 特になし（単体テスト、エッジケーステスト、障害モードシミュレーション、実機通信テストすべて実施済み）。

- **総合評価**: **【要修正 (Action Required)】**
  - **判定理由**:
    - 基本機能（AC-9.1〜AC-9.5: 新宿駅誤ジャンプの解消、OSM/GSIハイブリッド連携、スマートリランキング、候補ドロップダウンUI、XSSサニタイズ、API片肺運転耐性）は極めて高い品質で実装されている。
    - しかし、**検索非同期通信におけるリクエスト世代管理の欠如（遅延した古い検索結果によるドロップダウン・地図移動の上書きレースコンディション: BUG-005）** および **Enterキー連打等による同時並行実行防止フラグの欠如（OSM Nominatim API 1 req/sec 違反リスク: BUG-006）** の重大な障害モードが検出されたため、シニアコーダーによる是正改修が必要である。

## 3. 発見された不具合・課題一覧 (Issue票)

### [BUG-005]: `App.searchAddress` における非同期リクエスト世代管理の欠如によるレースコンディション
- **重大度**: **High**
- **関連要件/受け入れ基準**: AC-9, NFR-4, NFR-6, 12大検証項目の「7. 並行性」
- **再現手順**:
  1. 検索入力欄に「検索A（外部API応答に50ms以上かかる検索語）」を入力して検索を実行する。
  2. 検索Aの非同期通信が完了する前に、素早く別の「検索B（キャッシュ等で即座に応答する検索語）」を入力して検索を実行する。
  3. 検索Bが先に完了し、ドロップダウンに検索Bの候補リストが表示される。
  4. 遅れて検索Aの非同期通信が完了する。
- **期待される動作**:
  検索Aの通信完了時点で、すでに新しい検索Bが開始されているため、検索Aの結果は破棄され、検索Bの表示状態や地図位置が維持されること。
- **実際の動作**:
  検索Aの結果がそのまま `UIController.showSearchResults`（または単一高確度時の `updateLocation`）に引き渡され、ドロップダウンや地図移動先が古い「検索Aの結果」で上書きされてしまう。
- **証拠・ログ**:
  テスト `QA-RACE-01` の実行において、遅延した検索Aによってドロップダウン内容が検索Bから検索Aへと強制上書きされる現象を確認。
  ```text
  QA-RACE-01 検証: hasSearchB=false, hasSearchA=true
  ドロップダウン内に古い「検索Aの結果1」「検索Aの結果2」が残存。
  ```
- **考えられる原因**: 実装起因。
  `App.updateLocation` では `App.currentRequestId` によるリクエスト世代管理ガードが実装されているが、`App.searchAddress` には世代管理カウンタ（`currentSearchRequestId` 等）が導入されておらず、非同期通信（`await GeocodingService.search`）完了後の世代一致チェックが行われていない。
- **推奨される次の対応**: **シニアコーダーによる是正**。
  `App` クラスに `static currentSearchRequestId = 0;` を定義し、`searchAddress` 呼び出しごとにインクリメント。`await GeocodingService.search(...)` の直後に `if (this.currentSearchRequestId !== searchRequestId) return;` のガード判定を挿入する。

### [BUG-006]: `App.searchAddress` における同時並行実行防止フラグ（多重送信ガード）の欠如
- **重大度**: **Medium**
- **関連要件/受け入れ基準**: NFR-3（Fair Use Policy 1 req/sec 遵守）, NFR-4
- **再現手順**:
  1. 検索入力欄にキーワードを入力し、キーボードの Enter キーを高速連打する。
- **期待される動作**:
  検索処理中（通信中）は多重実行フラグによって新たな送信要求がブロックされ、外部API（特に OSM Nominatim）への連続過負荷リクエストが防止されること。
- **実際の動作**:
  検索ボタン自体は `disabled` になるものの、Enter キー連打による `submit` イベントや非同期多重呼び出しがそのまま並行実行され、短時間に Nominatim API へ複数回のリクエストが同時に発行される。
- **証拠・ログ**:
  テスト `QA-RACE-02` において、連打時に同一クエリのリクエストが並行して5回同時に発行されることを確認。
  ```text
  QA-RACE-02: 多重送信ガードが存在しないため、5回のリクエストが同時に発行される
  ```
- **考えられる原因**: 実装起因。
  `App` クラスに検索実行中フラグ（`isSearching`）が存在せず、フォーム送信イベントおよび `searchAddress` の入口で二重実行防止チェックが行われていない。
- **推奨される次の対応**: **シニアコーダーによる是正**。
  `App` クラスに `static isSearching = false;` を追加し、`searchAddress` の開始時に `if (this.isSearching) return;` でガードし、`this.isSearching = true;` をセット。`finally` ブロックで `this.isSearching = false;` に戻す。

### [BUG-007]: 「現在地を取得」ボタン押下時に候補ドロップダウンが明示的に非表示化されない問題
- **重大度**: **Low**
- **関連要件/受け入れ基準**: AC-9.5, ユーザビリティ
- **再現手順**:
  1. 検索を実行して候補ドロップダウンを表示させる。
  2. ヘッダーの「現在地を取得」ボタン（`#btn-current-location`）をクリックする。
- **期待される動作**:
  サンプルボタンやロゴクリック時と同様に、現在地取得処理の開始と同時に `UIController.hideSearchResults()` が明示的に呼び出され、ドロップダウンが即座にクローズされること。
- **実際の動作**:
  `btnLocation` のクリックリスナー内で `UIController.hideSearchResults()` が呼ばれておらず、外側クリックイベントのバブリング処理のみに依存しているため、キーボード操作やタッチ環境で閉じる挙動に曖昧さが生じる。
- **考えられる原因**: 実装起因。
  `js/app.js` の `btn-current-location` イベントリスナー内における `UIController.hideSearchResults()` 呼び出し漏れ。
- **推奨される次の対応**: **シニアコーダーによる是正**。
  `btnLocation.addEventListener('click', ...)` のハンドラ先頭に `UIController.hideSearchResults();` を追加する。

## 4. エスカレーション事項

- **アーキテクチャ・設計上の問題**: **【なし】**
  - 国土地理院APIとOSM Nominatim APIのハイブリッド構成、スマートリランキング計算式、候補ドロップダウン提示のUX仕様（ADR-05, ADR-06）は極めて妥当であり、アーキテクチャレベルの変更や再設計は一切不要である。
- **実装レベルの是正要請**:
  - 検出された3件の不具合（BUG-005, BUG-006, BUG-007）はすべて `js/app.js` のメインオーケストレータ層における非同期ガードおよびイベント調停の補強（約10行程度の追記）で完全に解決可能である。
  - シニアコーダーによる速やかな改修と、改修後の再検証（回帰テスト）を推奨する。
